# Normal 3D character document — format `limonat-character-3d` 1.0

Version 1.0.0 · 2026-10-11 · creator 1.1.0

This format belongs to the **Normal 3D** mode only. It shares nothing with the
Voxel document (`limonat-character`, see [SCHEMA.md](SCHEMA.md)): different
structure, ids, parameters and validator. Each mode refuses the other's
documents with a message that offers to switch modes.

| File | What it is |
|---|---|
| [`schema/limonat-character-3d.schema.json`](../schema/limonat-character-3d.schema.json) | JSON Schema (draft 2020-12), generated from the registry: every id, parameter, range and enum |
| [`schema/limonat-3d-asset-catalog.json`](../schema/limonat-3d-asset-catalog.json) | machine-readable list of every asset with its parameters, colours and fabrics |
| [`docs/N3D_ASSET_CATALOG.md`](N3D_ASSET_CATALOG.md) | the same catalog for people |
| [`examples/n3d/`](../examples/n3d/) | an AI output example, a "changes only" example, an invalid example (to see the error messages) and the 11 character presets |

All four are regenerated by `npm run gen` and checked by the unit tests, so
they always match the app.

## 1. Structure

```jsonc
{
  "format": "limonat-character-3d",      // required in saved files; optional in AI output
  "version": "1.0",                       // 1.x documents are accepted; unknown fields are ignored
  "mode": "normal3d",                     // a different mode is refused
  "meta": { "id": "n3d_…", "name": "Layla", "notes": "", "createdAt": "…", "updatedAt": "…" },
  "detail": "standard",                   // standard | high | advanced
  "body":  { "height": 1.66, "masculinity": 0.15, "muscle": 0.25, … },      // 29 numbers
  "face":  {
    "jawWidth": -0.3, "eyeSize": 0.25, …,                                  // 41 numbers, −1…1 (0 = average)
    "eyes":  { "iris": "#4A3020", "irisSize": 1, "pupil": 1, "sclera": "#F2EEE6",
               "lashLength": 1.2, "lashDensity": 1, "lashCurl": 0.6, "lashColor": "#1A1410",
               "heterochromia": null },                                     // second iris colour, or null
    "brows": { "styleId": "brow_rounded_01", "color": "#2A1B12",            // color null = hair colour
               "params": { "thickness": 1, "arch": 0.2, … } },              // 8 brow controls
    "facialHair": { "styleId": "facial_none", "params": {}, "colors": {} },
    "makeup": { "lipColor": "#A8505A", "lipAmount": 0.5, "blush": 0.3, "blushColor": "#D9776B",
                "eyeShadow": 0, "eyeShadowColor": "#6E5A7E", "eyeliner": 0 }
  },
  "skin":  { "tone": "#C08A64", "undertone": 0.3, "roughness": 0.52, "freckles": 0.15, "moles": 0.15,
             "wrinkles": 0, "blemishes": 0.1, "stubble": 0,
             "scars": [ { "at": "cheekLeft", "size": 0.5, "angle": 20 } ] },   // up to 6
  "hair":  { "styleId": "hair_long_wavy_01",
             "params": { "length": 1.1, "volume": 0.55, "part": "left", … },   // the style's own controls
             "colors": { "root": "#2B1B12", "tip": "#5A3A22", "highlight": "#8A6040" } },
  "outfit": [                                                              // up to 14 garments + footwear
    { "assetId": "top_blouse_01",
      "params":   { "fit": "relaxed", "neckline": "v", "sleeveLength": 0.75, "tucked": true },
      "colors":   { "main": "#F3E9DC" },
      "material": { "fabric": "silk", "pattern": "none", "patternScale": 1, "wear": 0, "hardware": "silver" } }
  ],
  "accessories": [ { "assetId": "neck_scarf_01", "params": { "wrap": "oneBack" }, "colors": {}, "material": {} } ]   // up to 12
}
```

* **Body** values are multipliers (1 = average) or 0…1 amounts; `height` is in
  metres (1.45–2.05). `masculinity` 0…1 blends feminine and masculine anatomy;
  `stylization` 0…1 goes from realistic to cartoon proportions.
* **Face** values are offsets from −1 to 1 (a few are 0…1).
* **Items** (`outfit`, `accessories`) carry only the parameters their asset
  declares: a T-shirt has `fit`, `length`, `sleeveLength`, `neckline`,
  `hemWidth`, `tucked`, `rolledSleeves`…; trousers have `fit`, `rise`,
  `legLength`, `legOpening`, `cuff`…. The catalog lists them per asset.
* **Order** of `outfit` does not matter: each garment has a layer number
  (top → mid → outer; full-body garments between). Items keep an optional
  `uid` (stable id used by the interface and in GLB node names).
* Colours are `#RRGGBB`. `#abc`, `abc` and lower case are accepted and
  normalised.

## 2. Validation

`validateN3D(input, { mode, base })` (`src/n3d/schema/validate.js`) never
throws. It accepts a whole document, a partial one, JSON inside prose or a
```` ```json ```` fence, or a `{ "character": { … } }` wrapper, and returns

```js
{ ok, doc, errors: [{ path, message }], warnings: [{ path, message }] }
```

| Kind | Examples | Effect |
|---|---|---|
| **error** | unknown asset id (with a "did you mean …?" suggestion), item in the wrong list (shoes in `accessories`), wrong type, enum value not offered, unknown fabric / pattern / hardware, Voxel document | that field is dropped |
| **warning** | number out of range (clamped), unknown parameter for this asset (with the list of its parameters), colour normalised, more than one pair of footwear (first kept), name too long, more items than the limits, unknown top-level field | fixed automatically |

`doc` is always complete and safe to build. **Replace** mode: missing parts
take default values (a new character). **Merge** mode: the input changes only
what it names on top of the current character (e.g. "make the jacket green").

Limits: 14 outfit items, 12 accessories, 6 scars, names up to 80 characters.

## 3. Versioning

`version` is `"1.0"`. Minor versions (1.x) only add optional fields and asset
ids; they stay readable by every 1.x creator (unknown fields are ignored with
a warning). Asset ids are permanent; a removed asset would be mapped to its
replacement in the validator, never reused for something else. A breaking
change would become `"2.0"` with a converter.

## 4. Where the document travels

* saved characters (browser / account library, *Download JSON*);
* AI output pasted into *AI import*;
* the export: `<name>.character3d.json`, inside the GLB (`extras.limonatCharacter3D.document`)
  and inside the metadata file — so any exported model can be reopened and
  edited in the creator.
